react-aria-live: regiones aria-live compatibles con lectores reales

Noviembre 2026 · Librerías · Por Diego Mena

Librería React para anuncios dinámicos en regiones aria-live (polite/assertive) compatible con VoiceOver en iOS/macOS, NVDA y JAWS, con hook useAnnouncer() y tipado estricto TypeScript.

Las regiones aria-live son el mecanismo estándar para anunciar contenido dinámico a lectores de pantalla, pero su comportamiento real difiere entre VoiceOver, NVDA y JAWS: un mismo patrón que anuncia en un lector queda mudo en otro. react-aria-live encapsula esos detalles de interoperabilidad en una API mínima y tipada.

El problema: anuncios que nadie escucha

Los errores más comunes son montar la región en vivo junto con el mensaje (el lector aún no la observa), cambiar aria-live dinámicamente o confiar en que un cambio de texto siempre se anuncia. VoiceOver en iOS, por ejemplo, es especialmente estricto con la estabilidad del nodo contenedor y con los tiempos de mutación.

useAnnouncer(): API mínima

El hook useAnnouncer() mantiene las regiones montadas desde el primer render y expone dos métodos: announcePolite para notificaciones rutinarias y announceAssertive reservado a errores críticos. Internamente aplica las técnicas que maximizan la compatibilidad real: nodos persistentes, atomicidad y control de mensajes repetidos.

SaveButton.tsx
import { useAnnouncer } from 'react-aria-live';

export function SaveButton() {
  const { announcePolite } = useAnnouncer();

  const handleSave = async () => {
    await save();
    announcePolite('Cambios guardados correctamente');
  };

  return <button onClick={handleSave}>Guardar</button>;
}

Probado contra lectores reales

La matriz de compatibilidad de la librería se validó con VoiceOver en iOS y macOS, NVDA y JAWS en Windows, documentando qué combinaciones de aria-live, aria-atomic y roles de status/alert anuncian de forma fiable en cada uno. Es el mismo rigor empírico que aplican los auditores lineales del ecosistema.

TypeScript estricto

Todo el paquete está tipado en TypeScript estricto, lo que convierte los errores de uso (por ejemplo, intentar anunciar antes de montar el proveedor de regiones) en errores de compilación y no en silencios en producción.

La librería es open source en github.com/ingelectronicadj/react-aria-live.
